# COSE v2 primitive known-answer vector 0003

- Status: **Test fixture only; not a production protocol approval**
- Profile under test: draft ADR 0003
- Artifact context: applicant acceptance
- Purpose: independently verify deterministic CBOR, COSE protected-header serialization, key-ID derivation, Sig_structure construction, P-256 ECDSA, low-S normalization, and tagged COSE_Sign1 assembly for a third artifact context.

## Security warning

The private scalar for this fixture is the public constant `1`. It is intentionally known to everyone and MUST NEVER be used for a real device, test installation, demo identity, or production signature. This fixture provides no secret key material. It exists solely for reproducible tests.

The payload below is a minimal cryptographic fixture, not the final ApplicantAcceptance schema. Artifact payload labels and required semantic fields remain subject to ADR 0003 review.

## Fixed inputs

- Curve: NIST P-256 / secp256r1
- Private scalar (fixture only): `01` left-padded to 32 bytes
- Public point: standard P-256 generator point (G)
- Hash: SHA-256
- COSE alg: ESP256 (`-9`)
- Signature generation: Python `cryptography` library ECDSA (non-deterministic nonce); S normalized to low half-order
- Protected content type: `application/vnd.familymesh.applicant-acceptance+cbor`
- External AAD: ASCII `FamilyMesh-ApplicantAcceptance-v2` followed by one zero byte

## Verification notes

- Public point is the P-256 generator corresponding to private scalar 1.
- Signature was generated by the Python `cryptography` library (non-RFC-6979 nonce) and S was normalized to the low half of the P-256 scalar range.
- The resulting DER-form ECDSA signature successfully verifies against the exact Sig_structure.
- Encodings were produced by a small deterministic-CBOR encoder and checked byte-for-byte.

This is a reproducible primitive vector for a third artifact context. It is not independent cross-implementation interoperability evidence and does not approve the draft wire profile. Before implementation approval, another implementation must reproduce the key ID, Sig_structure, and complete COSE object from the stated inputs.
